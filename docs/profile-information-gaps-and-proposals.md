作成日: 2026-11-09

## 1. 結論と現状のギャップ

現在のポートフォリオは、**「何を作ったか・どう実装したか（What / How）」の情報が非常に充実している**（Swiftアプリ17本、EkiHub、ブラウザゲーム2本、各技術の実装例、GitHub連携、専用紹介ページ）。

一方で、**「作者自身がどういう人物で、今どんな状況にあり、次に何を求めているか（Who / Context / Next）」の情報がかなり抽象的・最小限**にとどまっている。訪問者（採用担当者・エンジニア・依頼主）が作品に惹かれたあと、「この人に声をかけていいか？」「何年生・どんな経歴の人か？」を知ろうとした際に判断材料が不足している状態。

## 3. 不足している本人情報の一覧

### A. 基本プロフィール・現在のステータス（最優先）

1. **学年・卒業予定年（例：`2027年卒予定` / `学部3年` など）**
   - 「情報系の学生」としか書かれておらず、インターン対象なのか新卒対象なのかが判別できない。
2. **現在のステータス（Availability / 何を求めているか）**
   - 現在「長期インターンを探している」「新卒エンジニア就活中」「個人開発・業務委託（副業）の相談を受付中」など、どういう連絡を歓迎しているのかが明記されていない。
3. **所属（大学・学部・学科）または専攻領域の具体化**
   - アプリ一覧の `CIT-Campus-3D` から千葉工業大学（CIT）であることが推測できるものの、プロフィールには記載がない。大学名を明記するか、伏せる場合でも「情報工学科で〇〇（ネットワーク、画像処理、組込みシステム等）を専攻」と書くだけで解像度が上がる。
4. **氏名（漢字・ふりがな）と活動拠点**
   - 現在は英字の `Ryuto Hara` のみ。国内の採用担当者やクライアント向けに漢字表記（＋読み）があると親切。
   - フッターの時計に `TOKYO` とあるが、実際に「東京・首都圏ベース（リモート対応可）」なのかテキストでの記載がない。

### B. 経歴・バックグラウンド（「2025年6月以降のSwift開発」以外の文脈）

5. **開発体制・チーム開発や実務経験の有無**
   - インターン、ハッカソン、サークル・研究室、アルバイト等でのチーム開発経験があるか。
   - 逆に「17本のアプリ＋Web＋ゲームをすべて1人で企画・UIデザイン・実装・テスト・公開まで一貫して行っている」のであれば、その**自己完結力・推進力**自体が大きな強みになるため明文化すべき。
6. **プログラミングの原点・2025年6月以前の歩み**
   - `timeline.ts` が2025年6月から始まっているため、それ以前にどうやって C / Arduino や Python に触れ、なぜ iOS / macOS 開発にのめり込んだのかのストーリーが見えない。
7. **ハードウェア（C / Arduino）・Python の具体的な制作物**
   - Swift や Web は実画面つきで詳しく紹介されている一方、About や Skills で触れられている「C / Arduino の電子工作・IoT」「Python のデータ処理・機械学習」は具体的なエピソードが薄く、どんなものを作ったのか想像しにくい。
8. **資格・受賞歴・学業面の取り組み（もしあれば）**
   - 基本情報／応用情報技術者試験、TOEIC、ハッカソン出場・受賞歴、研究室のテーマなど。

### C. 人柄・信頼性・外部導線（「Trust」を補強する要素）

9. **本人のアイコン・アバター・写真**
   - サイト内に作者自身を表すビジュアル（実写、イラスト、GitHubアイコン等）が1つもない。顔や象徴的なアイコンがあるだけで「誰のポートフォリオか」が記憶に残りやすくなる。
10. **GitHub・メール以外の外部リンク（SNS・技術記事）**
    - Zenn / Qiita / note などの技術ブログ、X (Twitter)、Wantedly、LinkedIn、Speaker Deck など（運用しているものがあれば）。コードだけでなく「文章でどう思考を整理する人か」が伝わると信頼感が増す。
11. **今後挑戦したいこと・興味のある領域（Next Step）**
    - これだけの数のプロダクトを作った上で、「次はどんな技術・課題・環境に挑戦したいか」という未来向きのメッセージ。

## 5. 既存デザインを崩さない具体的な改善・実装案

現在のサイトの強みである「スクロール連動の粒子カード（`About.tsx`）」や「ミニマルなタイポグラフィ」を壊さずに情報を補うための具体案。

### 案1：`src/sections/About.tsx` の4枚のカード（`ABOUT_CARDS`）の文言具体化

カードの枚数（4枚）とレイアウト・文字数感を維持したまま、抽象的な1文を**「固有名詞・数字・具体例」が入った2〜3文**にアップデートする。

#### Before / After 比較案

* **01. 情報系の学生（`LEARNING`）**
  * **現状**:
    > 大学で情報工学を学びながら，授業の枠を超えて日々新しい技術を吸収しています．
  * **改善案（大学名を伏せる場合）**:
    > 大学で情報工学を専攻（202X年卒予定）．計算機科学やネットワークの基礎を学びながら，授業の枠を超えて「日常の不便を解消するソフトウェア」を自分の手でつくり続けています．
  * **改善案（大学名を出す場合）**:
    > 千葉工業大学で情報工学を専攻（202X年卒予定）．キャンパスマップアプリ「CIT-Campus-3D」など，学生生活の中で感じた課題を技術の力で解決することから開発を始めました．

* **02. iOS / macOSアプリ開発（`APP DEVELOPMENT`）**
  * **現状**:
    > 2025年6月から，Swift / SwiftUI で iPhone・Mac のアプリを17本つくり，ソースコードを公開しています．
  * **改善案**:
    > 2025年6月から Swift / SwiftUI での個人開発を本格化し，iPhone・Mac 向けに17本のプロダクトを制作．企画・UI設計・実装・テストまで一貫して1人で手がけ，すべてのソースコードを GitHub に公開しています．

* **03. 組込み・電子工作（`HARDWARE`）**
  * **現状**:
    > C / Arduino を使ったハードウェア寄りの開発も好きで，ソフトとハードの両面から物事を考えます．
  * **改善案**:
    > C / Arduino でのセンサー制御や電子工作がものづくりの原点です．低レイヤや通信の仕組みを意識できるからこそ，Bonjour や WebRTC などで端末同士をつなぐアプリ開発にもその視点が活きています．

* **04. 「Trust」を軸に（`GUIDING PRINCIPLE`）**
  * **現状**:
    > 「信頼されるソフトウェア」を目標に，使う人の体験を最優先した設計と丁寧な実装を心がけています．
  * **改善案**:
    > 目標は「毎日安心して使える，信頼されるソフトウェア」．迷わない導線と壊れにくい設計を両立させ，今後は個人開発で培った瞬発力を活かして，より多くの人に届くプロダクト開発に挑戦したいと考えています．

### 案2：`About.tsx` 下部 または `Contact.tsx` 左カラムへの「Profile Spec（早見表）」の追加

長い自己紹介文を増やすのではなく、Apple やモダンなポートフォリオのように**コンパクトな定義リスト（`<dl>`）形式のスペック表**を1つ置くと、デザインの世界観を保ったまま必要な属性情報を網羅できる。

#### 配置イメージ（`Contact.tsx` の左カラム、または `About.tsx` の直後）

```tsx
// 表示項目の例（データ構造案）
export const PROFILE_SPECS = [
  { label: 'Name', value: '原 〇〇 / Ryuto Hara (HR0101)' },
  { label: 'Education', value: '情報工学専攻（202X年卒業予定）' },
  { label: 'Location', value: 'Tokyo / Chiba, Japan（リモート可）' },
  { label: 'Focus', value: 'iOS & macOS (SwiftUI) / Web (Next.js) / 端末間連携' },
  { label: 'Status', value: '長期インターン・開発のご相談 受付中' },
] as const;
```

* **ポイント**:
  * `Contact.tsx` の左カラム（現在はメールとGitHubの2枚のタイルのみ）の上部に、緑色の小さなドット付きのステータスバッジ（例：`● 現在、インターン・お仕事のご相談を受け付けています`）と上記のミニマムなプロフィール欄を置くと、「連絡する直前に相手の状況がわかる」ため導線として最も自然。

### 案5：`src/data/skillExamples.ts` への Python / ハードウェア具体例の追加

現在 `SKILL_EXAMPLES` には Swift 系と React/Next.js、Tailwind CSS、Git/GitHub の計13件が登録されているが、上位の4大スキルカード（`Skills.tsx`）に掲げている **Python** と **C / Arduino** の具体例が下のリスト（`SkillExamples`）には入っていない。

* **Python**: `AeroPath` や `FraTerm` の1行説明を追加（リポジトリへのリンクつき）。
* **C / Arduino**: 制作した電子工作や組込みプロトタイプの具体例を1件追加。

これにより、「4枚のスキルカードに書いてあること」と「下の実績リスト」が100%一致し、サイト全体のテーマである「Trust（根拠のある紹介）」がさらに強固になる。
