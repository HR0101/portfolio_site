# United Carriers：アニメーション・遊び心の全体カタログ

調査日：2026-11-07〜2026-11-08（JST）  
対象：[unitedcarriers.com](https://unitedcarriers.com/)  
目的：RHポートフォリオで応用できるように、演出を見た目・発火条件・実装方式に分解する。サイトの実装変更は行っていない。

## この資料の読み方

公開HTML、埋め込みCSS、配信JavaScriptを横断し、ホームだけでなく主要な下層ページ・記事・物販・404まで、識別できた演出パターンを棚卸しした。同じテンプレートの記事や同じ種類のリンクは、重複をまとめている。

- **コード確認**：配信中の処理やスタイルを確認したもの。すべての挙動を実画面で再現したという意味ではない。
- **画面＋コード確認**：画面キャプチャの表示内容と配信処理を照合したもの。動きの全過程や直接操作の成功を意味しない。
- **直接操作確認**：入力の前後で対応する表示変化を比較できたもの。具体的な範囲と未確認部分は[実画面の観測記録](united-carriers-live-observations.md)に記載。
- **応用案**：このポートフォリオ向けの提案。参照サイトにその機能があるという意味ではない。
- 時間・補間係数は、明記したものだけ配信コードの値。`scrub`内の`duration`はタイムラインの相対比率であり、その秒数で自動再生される意味ではない。

実画面では船・海、点描フッター文字、Heroの地球と航路、初回ローダーの一時点、CTA円、記事行のhover状態、飛行機とロゴ一覧を確認した。ただし、**粒子文字がマウスで崩れて復元する一連の動作は直接観測できていない**。別セッションではcanvas相当の位置が空白になり、操作ツールにも接続エラーが出ている。全ページの全状態やスマホ実機を網羅した検証ではない。

RHへの具体的な組み込み方は[演出設計](../../plans/united-carriers-portfolio-motion-design.md)、136項目それぞれの採用・保留・見送りは[全要素の応用判断](../../plans/united-carriers-adoption-map.md)を参照。

## 1. 全体の体験設計

一番の特徴は、スクロールを「次の情報へ進む操作」と「物流の旅を動かす操作」に兼用させていること。文章の下に動画を置く構成から一歩進み、地球・荷役・道路・海・雲・飛行機を、章のつなぎとして使っている。[ホーム][home]、[Home配信コード][home-js]

| 軸 | 具体的な仕掛け | 応用するときに残す考え方 |
| --- | --- | --- |
| 世界観の連続 | 宇宙・地球から地上、海、空へ展開 | セクションごとに別の装飾を足すより、一つのモチーフを受け渡す |
| 操作と映像の対応 | スクロール位置で荷役や車両の動きが進む | 入力に対して何が変わるかを明確にする |
| 意外性 | スクロール速度を車の速度計にする | 既存の操作を、そのサイトらしい計器や反応に読み替える |
| 大小の対比 | 大きな風景と、小さなラベル・点・数値 | 大きい演出だけでなく細部の反応も同じ世界観に揃える |
| 円と点の反復 | 地球、カーソル、進捗リング、ローダー、CTA、地図 | 一つの造形ルールを複数の場所で使う |
| 視点の変化 | クレーン・トラックの連番画像、船の引き、飛行機と影 | 単純なフェードの代わりに「視点が移った」と感じさせる |
| 読む順番の演出 | 行マスク、文字のグラデーション、段階的な表示 | 重要な見出し→補足→操作の順で視線を導く |

色の構成は、黒・白の情報面、オレンジのアクセント、青い地球や海、車両やコンテナの色を切り替えるもの。配信スタイルにはアクセントとして`#f50`がある。背景の色を変えるだけでなく、景色そのものを境界として使う点が重要。[共通CSS][css]、[ホーム][home]

### 小さな演出を組み合わせる順序

「背景色が変わる」「文字が入れ替わる」「矢印が抜ける」「カーソルが変わる」を、同じホバーにまとめている。一つずつ強くするより、開始のタイミングと向きを揃えることがこの印象の再現につながる。

## 4. ホームの連続シーン

基本の流れ：

```text
地球と文字の登場
  → 空・地球の縁を使った導入の接続
  → 写真・実績数値
  → クレーンで積む
  → トラックが走る／道路と視点が変わる
  → 海と貨物船へ切り替わる
  → 雲を通り抜ける
  → 飛行機と影
  → 実績・ロゴ・記事・FAQ
  → 波紋CTA・粒子フッター
```

参照：[ホーム][home]、[Home配信コード][home-js]、[海面モジュール][ocean-js]。

| ID | 章・対象 | 発火条件 | 何が起きるか | 実装・再現の観点 |
| --- | --- | --- | --- | --- |
| H01 | Heroの文字・ボタン | ロード後／ページへ入る | ラベル、見出し、説明、ボタンを順に登場させる | 行マスク＋revealを一つのタイムラインへ |
| H02 | 地球の登場 | Hero開始 | 小さくずれた状態から地球を大きくし、光とぼかしを整える | scale、位置、opacity、blur。`expo.out`、`back.out(1.3)`等 |
| H03 | ドット地球 | Hero表示中 | 点状の地球が自転する | WebGL。自動回転量はフレーム時間で補正 |
| H04 | 地球の操作 | PC等でドラッグ | 自転の鑑賞から、自分で回す操作へ移れる | 操作中は自動回転を控える。スマホではcontrols無効 |
| H05 | 地球上の経路 | 地球表示中 | 拠点と弧状の経路を重ね、接続網を表す | 空港・flightデータ、`showArcs:true`。実物流のライブ追跡と同一視しない |
| H06 | 地球・星の退場 | 下へスクロール | 地球を暗くして消し、星も少し拡大しながら消す | scrub、brightness、opacity、scale |
| H07 | Heroと導入の重なり | Heroを抜ける | 大きい円弧状の背景で、黒い空間から明るい情報面へつなぐ | 背景画像・重なり・大きな高さを含む構成。色のフェードだけでは再現しきれない |
| H08 | 導入写真と見出し | 導入へ到達 | 風景・大見出し・本文を、異なる層として見せる | `.home-intro-thumb`等、revealとscrubを併用 |

### 特に真似する価値がある3つ

**スクロール速度計**：スクロールの「量」だけでなく「速さ」に意味を与える。RHなら、ビルドの勢い・データ転送・軌道の粒子などに置き換えられる。数値を実際の処理性能と誤認させない表現にする。

**風景を使う章の接続**：カードが消えて別のカードが出るのではなく、前の章の要素が次の景色を覆う。RHなら、アプリアイコンや開いたウィンドウを、次の紹介画面へ受け渡す発想が合う。

**演出の主役を受け渡す構成**：地球→コンテナ→トラック→船→飛行機という役割の移動。RHなら、RHロゴ→アプリアイコン→実際のアプリ画面→コードや成果、という流れにできる。

## 6. スマホでの組み替え

コード上の主な境界は767px・991px付近。CSSには992px基準もあり、個々の条件をそのまま一つの値へ統合しないこと。[Home配信コード][home-js]、[layoutモジュール][layout-js]

| 要素 | PC側 | スマホ側の処理 |
| --- | --- | --- |
| カスタムカーソル | 遅延追従・残像・進捗・役割変更 | 991px以下等では初期化しない |
| 地球 | 自転＋手動操作 | 自転は残すが手動controlsを無効化、カメラ距離や点の密度を変更 |
| 一般のreveal | 多くのセクションで有効 | 共通クラスでは原則省略し、必要なものだけ`allowMobile`で有効化 |
| クレーン | PC用の連番・横展開の長いタイムライン | mobile用のlift／rotateや専用レイアウトに分岐 |
| 海 | WebGLの海面・カメラを使用 | 767px以下側は画像と拡大縮小を使う別シーン |
| 飛行機 | 大きい曲線マスク・影・雲を連動 | タブレット・スマホそれぞれに別の値・構成 |
| サービス名 | 連続マーキー等 | Swiperによるスライドへ |
| 業種詳細 | スクロールで積層・説明 | ポップアップへ |
| 選考プロセス | ポインター位置に応じたマスク | タップで本文展開 |
| 団体カード | ハーフトーンのhover | タップ開閉 |
| チーム | loopするスライダー | 端を持つスライダー |

ここは「同じアニメーションを小さくする」ことより、端末ごとに操作を成立させる発想を参考にする。実機の見え方とタッチの挙動は別途確認が必要。

### 画像連番の設計上の特徴

- canvasへ進捗に対応するframeを描く。
- 全画像を一括で描画する構成ではなく、windowed／progressiveな読込を使う。
- 並行取得数6等の制限がある。
- 一部のシーンは奇数frameを間引く設定を使う。
- スクロール区間とframe範囲を結ぶため、前に戻せば映像も逆向きに戻せる構成。
- この方式では、画像容量・先読み・canvasの解像度・静止画への代替が品質を左右する。

参照：[frame-sequenceモジュール][frame-js]、[Home配信コード][home-js]。

## 8. RHサイトへの置き換え案

この章は提案。現在のRHサイトと参照サイトを比べた実装候補であり、今回の作業では実装していない。

| 優先 | 現状・出発点（Before） | 取り入れる案（After） | 理由（Why） |
| --- | --- | --- | --- |
| 1 | RHとアプリアイコンの公転がある | 地球の代わりにRHを中心とし、次に紹介するアプリだけを手前へ受け渡す | 既存の主役を使って、章をつなげられる |
| 1 | アプリカード→詳細ページへ移る | 押したアイコンやアプリ画面が次ページのHeroへ連続する | サイトの旅を「アプリを開く体験」に置き換えられる |
| 1 | 通常のリンク・矢印 | 文字の縦入れ替え、矢印の右上への抜け、走る下線を統一 | 小さい変更でもサイト全体に一貫した反応が出る |
| 1 | 最後の連絡導線 | 新しい鳥のロゴや円を使ったCTA、位相差のある波紋 | 円のモチーフをHeroから終端までつなげる |
| 2 | アプリ一覧で静止した画面を見せる | ホバーしたアプリの画面プレビューが、限られた範囲でカーソルへ追従 | 一覧で実物を覗く楽しさを作れる |
| 2 | 開発の軌跡が縦に続く | 一つのウィンドウが、企画→画面→コード→成果に変わる短いscrubシーン | クレーンの物語を、アプリ制作の物語へ翻訳できる |
| 2 | フッターのブランド表示 | RHの点群がカーソルを避けて元に戻る | 最後に触って遊べる場所を作れる |
| 2 | 静止したGitHub指標 | 数値の初回カウント＋スクロール速度に応じる控えめな装飾 | 実績の意味と操作の遊びを分けて見せられる |
| 3 | 各アプリに独立した背景 | アプリの世界観の色・画面を、次の章を覆う前景に使う | 物流風景をそのまま持ち込まず、アプリ固有の景色にできる |
| 3 | 大きい一枚のHero画像 | 本当に必要な紹介だけ、操作動画・画像連番で説明する | 機能の理解につながるところへ演出のコストを使える |

### 第一段階の組み合わせ

最初に比較するなら、**G08〜G13のリンク反応＋H01〜H07のHero接続＋G27の終端CTA**。これで大きい章と小さい反応の両方に共通ルールができる。その後、G28の粒子やG06の追従プレビューを足すと、触って遊べる場所を増やせる。

今回の参照を理由に、既存のパレットや通常の操作まで長い演出にする必要はない。作品紹介の演出と、移動・検索・入力の反応は用途に合わせて扱う。

## 9. 実装時の確認項目

参照サイトの存在する動きをそのまま品質保証として扱わず、RH側で以下を確認する。

- [ ] スクロール連動か、自動ループか、一回だけの登場かを要素ごとに決める。
- [ ] 固定する区間の長さと、ユーザーが読み終えるまでの距離を合わせる。
- [ ] 逆スクロール、速いスクロール、区間途中へのアンカー移動を試す。
- [ ] 読込前の画像・連番が揃わない状態でも、主な説明とリンクが使える。
- [ ] 経路切り替えでcanvas、画像、イベント、timelineを解放する。
- [ ] 画面外・非表示タブでは、重いループを停止する。
- [ ] タッチではhoverを前提にしない。通常のリンク操作を維持する。
- [ ] 動きを減らす設定では、大きい移動・回転・カメラ変化を静止画や短いフェードへ置き換える。
- [ ] カスタムカーソルがなくても、リンク・ドラッグ・前後操作が分かる。
- [ ] ポップアップとメニューのフォーカス、Escape、背景の操作抑制を確認する。
- [ ] 速度計等の装飾値が、実際のビルド時間・ネットワーク速度・実績と誤認されない。
- [ ] スマホ実機と本番ビルドで、読込量・フレームの安定性を確認する。
